## 1. Принципы

1. Тесты — часть Definition of Done, а не «после релиза».
2. Тестируется `Game.Core`; Godot для тестов не требуется.
3. Каждое правило GDD имеет тест; каждый баг — регрессионный тест.
4. Тесты детерминированы: фиксированные сиды, никакой зависимости от времени,
   сети, файловой системы и порядка выполнения.
5. Публичное поведение важнее реализации: тесты не привязаны к приватным деталям.
6. Тест не «подгоняет» ожидание под текущий баг: сначала решение, потом число.

## 3. Команды

```powershell
dotnet test EidolonSeamWars.sln -c Release
powershell -NoProfile -ExecutionPolicy Bypass -File tools/scripts/test.ps1
```

На Unix:

```bash
bash tools/scripts/test.sh
```

Фильтр по классу:

```powershell
dotnet test tests/Game.Core.Tests/Game.Core.Tests.csproj --filter "FullyQualifiedName~HexTests"
```

Результат этапа 03: **262 теста, 0 провалов**
(52 инфраструктурных + 160 доменных + 14 прогрессии + 36 контента).

## 5. Соглашения

- Имена тестов: `Method_StateUnderTest_ExpectedBehavior` (английский).
- Комментарии и сообщения ассертов — русский.
- AAA: Arrange / Act / Assert, без логики в ассертах.
- Параметризация — `[Theory]` / `[InlineData]`, если проверяется таблица значений.
- Запрещены `Thread.Sleep`, реальные файлы вне temp, сетевые вызовы.
- Для временных файлов — уникальный каталог в `Path.GetTempPath()` с очисткой.
- Ожидаемые исключения проверяются с параметром и сообщением, а не «любое исключение».

## 6. Детерминизм

- RNG: только `SeededRandom`/`RngStreams`; сид задаётся в Arrange.
- Один и тот же сид и порядок вызовов обязаны давать одинаковый результат.
- Тесты не должны зависеть от текущего времени; `DateTimeOffset.UtcNow` в домене
  допускается только через явную передачу.
- Порядок тестов не гарантируется: общее состояние между тестами запрещено.
- Для будущих реплеев: golden-тест журнала команд (этап 05/09).

## 8. Контент и валидатор

- Валидатор запускается как `SimRunner validate` и в тестах.
- Тесты контента обязаны падать на: дубликате ID, отсутствующей ссылке,
  неизвестной `schemaVersion`, расхождении ключей локализации, превышении лидерства.
- Контент не дублируется в тестах: используется реальный `game/content/core`
  (`RealContent`), плюс синтетические паки в памяти для негативных сценариев.
- Реальный контент должен проходить валидатор без ошибок и без `CONTENT_RULE_UNKNOWN`.
- `tools/scripts/check-localization.ps1` проверяет структуру локализации отдельно.
- `validate` завершается кодом 0 при успехе, 1 при ошибках, 2 при ошибке запуска.

## 9. CI

`.github/workflows/ci.yml` (заготовка): restore → build → test → validate.
CI собирает корневой solution вместе с Godot-слоем через `Godot.NET.Sdk`.
CI не требует Git для локальной работы.
Локальная проверка перед сдачей: `dotnet build`, `dotnet test`, `validate`.

## 10. Покрытие и приоритеты

- Числовой порог покрытия не фиксируется до появления домена; приоритет — правила,
  а не проценты.
- Обязательно покрываются: урон, мораль, лидерство, ветеранство, побег/выкуп, захват,
  дневной тик, сейвы, валидатор.
- Не покрываются unit-тестами: рендер, звук, ввод, анимации (ручная проверка).
- Провал теста блокирует сдачу задачи.
