## 1. Цели

- Восстанавливать причину бага по логам без воспроизведения.
- Проверять детерминизм: сиды, броски, порядок команд.
- Диагностировать контент и моды до запуска боя.
- Не раскрывать секреты и не засорять диск.

Логирование обязательно во всех уязвимых местах (AGENTS.md, инвариант 11).

## 2. Уровни

| Уровень | Когда использовать |
|---|---|
| `Trace` | пошаговые детали симуляции, отдельные броски, доставка событий |
| `Debug` | диагностика для разработки, загрузка файлов, решения ИИ |
| `Info` | штатный жизненный цикл: старт сессии, загрузка контента, сейв, конец боя |
| `Warning` | восстановимая проблема: отсутствующий ключ локализации, конфликт модов |
| `Error` | операция не выполнена: сейв не записан, команда отклонена |
| `Critical` | продолжение невозможно: повреждён core-контент, краш |

Уровень по умолчанию для релиза — `Info`; для отладки — `Debug`/`Trace`.
Фильтрация выполняется реализацией `IGameLogger`; ядро проверяет `IsEnabled` перед
построением дорогих полей.

## 3. Категории

| Категория | Содержимое |
|---|---|
| `Content` | загрузка, схемы, реестр, валидация, отсутствующие ссылки |
| `Mods` | манифесты, порядок загрузки, конфликты, отключение модов |
| `Save` | запись, чтение, миграции, слоты, повреждённые файлы |
| `Battle` | команды, сиды, броски урона/критов/морали, контратаки, ветеранство |
| `Economy` | дневной тик, доход, прирост, найм, траты |
| `Map` | движение, pathfinding, туман войны, захват объектов |
| `AI` | стратегические и тактические решения, веса, отказы |
| `Hero` | левелап, побег, выкуп, плен, артефакты |
| `UI` | переходы экранов, недоступные действия, ошибки presentation |
| `Settings` | применение настроек, смена языка, громкость |
| `Loc` | отсутствующие ключи, паритет RU/EN, форматирование |

Категория — стабильная строка из перечня. Новые категории добавляются в этот документ
до использования в коде.

## 4. Формат записи

Одна запись — одна JSON-строка (JSON Lines). Пример:

```json
{"ts":"2026-11-13T12:34:56.789Z","level":"Info","category":"Battle","sessionId":"s-01J8...","correlationId":"battle-42","message":"Применена команда атаки","fields":{"attackerStack":"slot-2","targetStack":"slot-4","seed":"12345"}}
```

| Поле | Тип | Обязательно | Комментарий |
|---|---|---|---|
| `ts` | string | да | ISO-8601 UTC с миллисекундами |
| `level` | string | да | `Trace`…`Critical` |
| `category` | string | да | из таблицы §3 |
| `message` | string | да | русский текст, без персональных данных |
| `sessionId` | string | да в runtime | идентификатор запуска игры |
| `correlationId` | string | нет | `battleId`, `armyId`, `saveId`, `modId` |
| `fields` | object | нет | значения только строки/числа/булевы |

Требования: UTF-8, LF, без многострочных сообщений, без вложенных объектов
(для вложенности использовать плоские ключи `unit.id`).

| Лечение и регенерация | Debug | Battle | `unitId`, `amount`, `round` |

## 6. Идентификаторы корреляции

- `sessionId` создаётся один раз на запуск и передаётся во все записи.
- `battleId` — на каждый бой; используется во всех боевых командах и бросках.
- `armyId`, `heroId`, `settlementId` — доменные ID, а не индексы UI.
- `saveId` — на каждую операцию сохранения/загрузки.
- `modId` — на загрузку и конфликты модов.
- Запрещено использовать в корреляции случайные Guid в доменной логике:
  идентификаторы создаются на границе (UI/SimRunner) и передаются внутрь.

## 7. Файлы и ротация

- Каталог: `logs/` (в `.gitignore`, кроме `.gitkeep`).
- Имя: `eidolon-YYYYMMDD-HHmmss.log` на сессию.
- Ротация: 5 файлов по 10 МБ; при переполнении старейший удаляется.
- Дублирование в консоль: `Info+` в релизе, `Debug+` в dev-сборке.
- Ошибки записи лога не должны ронять игру: реализация логирует в stderr и продолжает.
- Godot-слой и SimRunner используют один формат.

## 8. Crash-отчёт

При необработанном исключении:

1. Записать `Critical` с типом и сообщением исключения.
2. Сохранить crash-отчёт в `logs/crash-YYYYMMDD-HHmmss.json`.
3. Включить последние 200 строк журнала и стек исключения.
4. Не включать пути с именем пользователя, если это возможно; заменять на `<home>`.
5. Показать игроку путь к отчёту, не показывать стек в игровом UI.

## 9. Безопасность и приватность

- Запрещено логировать содержимое чужих файлов и персональные данные.
- Пути к сейвам логируются относительно каталога игры.
- Секреты (токены, ключи) не попадают в логи даже на уровне `Trace`.
- Мод-контент логируется по ID, а не полным текстом.

## 10. API ядра

```csharp
using Game.Core.Diagnostics;

if (logger.IsEnabled(LogLevel.Debug))
{
    logger.Log(LogEvent.Create(
        LogLevel.Debug,
        "Battle",
        "Применена команда атаки",
        sessionId: sessionId,
        correlationId: battleId,
        fields: new Dictionary<string, string>
        {
            ["actor"] = "slot-2",
            ["target"] = "slot-4",
            ["round"] = "3"
        }));
}
```

- `LogEvent` иммутабелен, время — UTC.
- `IGameLogger` не бросает исключений из `Log`.
- Реализации: `ConsoleGameLogger` (SimRunner, этап 03), `GodotGameLogger`
  (Godot, этап 03), тестовая (используется в тестах). Файловая реализация,
  ротация и crash-отчёт — этап 09.

## 11. Проверка

- Каждая обязательная точка из §5 покрывается тестом или ручным сценарием.
- Сиды и броски проверяются на воспроизводимость: два прогона с одним сидом дают
  одинаковые записи (без учёта времени).
- Отсутствие ключа локализации проверяется тестом паритета и ручным переключением языка.
- Ротация и crash-отчёт проверяются на этапе 09.

## 12. Статус этапа 03

Реализовано: `LogLevel`, `LogEvent`, `IGameLogger`; `EventBus` пишет `Trace`/`Error`
в переданный логгер. `ConsoleGameLogger` пишет в консоль SimRunner,
`GodotGameLogger` — через `GD.Print`/`GD.PushWarning`/`GD.PushError`; оба
используют категории из §4. `ContentLoader`, `ContentMerge`, `ContentValidator`
и `LocalizationResolver` логируют загрузку, порядок паков, переопределения,
итоги валидации и промахи ключей. `BootController` дополнительно печатает
каждое предупреждение загрузчика, merge и валидатора отдельной строкой, чтобы
пропущенные файлы правил и необязательные языки были видны в журнале Godot.
Файловой реализации, ротации и crash-отчёта пока нет — это этап 09.
