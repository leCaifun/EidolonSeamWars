## 1. Принципы

- Локализация с первого дня: обязательны RU и EN (AGENTS.md, инвариант 9).
- В коде и JSON — только ключи, никогда не готовый текст.
- Ключ стабилен; изменение ключа = миграция контента и сейвов.
- RU и EN обязаны иметь одинаковый набор ключей; расхождение — ошибка.
- Остальные языки — данные: они не блокируют сборку, но их пропуски логируются.
- Список языков и их статусы — источник истины в `languages.json` (ADR-026).
- Термины проекта переводятся по [docs/GLOSSARY.md](GLOSSARY.md).

## 2. Файлы и формат

```
game/content/core/localization/
├── languages.json     манифест языков (источник истины)
├── ru.json            обязательный язык
├── en.json            обязательный язык, глобальный фолбэк
├── es.json, de.json, …
└── …
```

Каждый языковой файл — объект с фиксированной формой:

```json
{
  "schemaVersion": 1,
  "id": "core.localization.en",
  "language": "en",
  "status": "complete",
  "fallback": null,
  "entries": {
    "language.en.name": "English",
    "faction.brass.name": "Brass March"
  }
}
```

| Поле | Тип | Правило |
|---|---|---|
| `schemaVersion` | int | поддерживаемая версия схемы (`1`) |
| `id` | string | стабильный ID файла, `core.localization.<code>` |
| `language` | string | код языка; совпадает с именем файла и записью в `languages.json` |
| `status` | string | `complete`, `draft` или `experimental`; совпадает со статусом в `languages.json` |
| `fallback` | string? | код языка фолбэка; `null` у обязательных языков |
| `entries` | object | плоский словарь `ключ → строка`; вложенность запрещена |

Правила формата:

1. Кодировка UTF-8, LF, финальный перевод строки.
2. `entries` — только `строка → строка`; массивы, объекты и числа запрещены.
3. Неизвестное поле в языковом файле — ошибка чтения (инвариант проекта).
4. Лишние ключи относительно `en` запрещены (ошибка `LOC_EXTRA_KEY`).
5. Пропуски ключей в `ru`/`en` — ошибка паритета; в остальных языках — предупреждение.
6. Моды добавляют свои языковые файлы в `mods/<modId>/localization/` с префиксом
   ключей `modId.`; при совпадении ключа значение мода переопределяет core.

## 3. Список языков и статусы

`languages.json` содержит `defaultLanguage` (`ru`), `fallbackLanguage` (`en`),
`requiredLanguages` (`ru`, `en`) и массив `languages`. Запись языка:

```json
{
  "code": "la",
  "nameKey": "language.la.name",
  "script": "Latn",
  "status": "complete",
  "visibleInSettings": true,
  "fallback": "en",
  "requiresFontReview": true
}
```

| Поле | Правило |
|---|---|
| `code` | код по ISO 639; уникален |
| `nameKey` | ключ локализации названия языка |
| `script` | письменность: `Latn`, `Cyrl` и т. п. |
| `status` | `complete`, `draft`, `experimental` |
| `visibleInSettings` | показывать язык в настройках |
| `fallback` | язык фолбэка; `null` — использовать глобальный |
| `requiresFontReview` | требуется проверка шрифтового покрытия |

Статусы:

| Статус | Значение | Валидатор | Настройки |
|---|---|---|---|
| `complete` | полный проверенный перевод | пропуски — предупреждение (`LOC_COMPLETE_KEYS_MISSING`) | показывается, если `visibleInSettings=true` |
| `draft` | черновой перевод | пропуски — предупреждение (`LOC_OPTIONAL_KEYS_MISSING`) | скрыт, пока не станет `complete` |
| `experimental` | экспериментальный перевод | пропуски — предупреждение | скрыт по умолчанию |

Зарегистрированные языки (26):

| Группа | Языки |
|---|---|
| Обязательные (`complete`, видны) | `ru`, `en` |
| `complete`, скрыты в настройках | `es`, `de`, `pt`, `it`, `fr` |
| `complete`, виден, нужна проверка шрифта | `la` |
| `draft` | `uk`, `be`, `pl`, `cs`, `sk`, `sl`, `bg`, `mk`, `sr`, `hr`, `bs` |
| `experimental`, нужна проверка шрифта | `rue`, `cu`, `szl`, `csb`, `hsb`, `dsb`, `cnr` |

Языки с `requiresFontReview=true` (обязательно для валидатора):
`la`, `cu`, `rue`, `szl`, `csb`, `hsb`, `dsb`, `cnr`.
Для них валидатор требует флаг `requiresFontReview=true` (`LOC_FONT_REVIEW_REQUIRED`),
а фактическая проверка покрытия шрифта — отдельная задача (см. KNOWN_ISSUES).

## 4. Ключи

Формат: `<domain>.<type>.<group>.<name>[.<field>]`.

| Префикс | Назначение | Пример |
|---|---|---|
| `core.` | служебный префикс контента ядра | `core.unit.brass.militia.name` |
| `unit.` | юниты | `unit.brass.militia.desc` |
| `faction.` | фракции | `faction.brass.name` |
| `hero.` / `hero_class.` | герои и классы | `hero.ash.selha.name` |
| `ability.` / `spell.` | способности и заклинания | `spell.root.thorns.name` |
| `building.` / `settlement.` | здания и поселения | `settlement.brass.desc` |
| `map_object.` / `resource.` | объекты карты и ресурсы | `map_object.mine_gold.name` |
| `ui.` | элементы интерфейса | `ui.menu.new_game` |
| `log.` | сообщения журнала | `log.save.write_failed` |
| `error.` | пользовательские ошибки | `error.leadership.exceeded` |
| `help.` | справка | `help.battle.retaliation` |

Правила:

1. Сегменты — `lower_snake_case`, латиница.
2. Ключ не содержит номеров версий и дат.
3. Имя записи контента: `<id>.name`, описание: `<id>.desc`.
4. Не сокращать слова до неоднозначности (`dmg` → `damage`).
5. Один ключ = один смысл; не переиспользовать для разных контекстов.
6. Валидатор собирает ключи, на которые ссылается контент (`nameKey`,
   `descriptionKey`, `rankNameKeys`, опции объектов карты и т. п.), и требует
   их наличия в `ru` и `en`.

## 5. Плейсхолдеры и числа

- Плейсхолдеры — `{name}`, `{count}`, `{gold}`; порядок задаётся строкой, не позицией.
- Форматирование чисел — по текущей культуре, но боевые значения всегда целые.
- Проценты в UI — целые с символом `%`; в логах — промилле отдельным полем.
- Даты — ISO в логах, локализованный вид в UI.
- Множественное число: для RU/EN используются отдельные ключи
  `...one` / `...few` / `...many` / `...other`; упрощённый вариант MVP —
  `{count} шт.` без склонения, если это читаемо.
- Не склеивать предложения из фрагментов: порядок слов различается.

## 6. Фолбэк и отсутствующие ключи

Резолвер (`LocalizationResolver`) ищет ключ по цепочке:

1. выбранный язык;
2. локальный `fallback` языковой таблицы;
3. `fallback` из записи языка в `languages.json`;
4. глобальный `fallbackLanguage` (`en`);
5. если ключа нет нигде — возвращается сам ключ как строка.

Защита от циклов: язык, уже посещённый в цепочке, повторно не рассматривается.

При полном промахе пишется лог `Warning`, категория `Loc`, поля `key` и `language`.
UI обязан показать либо ключ, либо явный маркер `[<key>]`, но не пустоту.

Правила валидации:

1. Пропуск в `en` или `ru` — ошибка (`LOC_KEY_MISSING_EN`, `LOC_KEY_MISSING_RU`).
2. Расхождение наборов `ru`/`en` — ошибка (`LOC_REQUIRED_KEY_MISMATCH`).
3. Лишний ключ в необязательном языке — ошибка (`LOC_EXTRA_KEY`).
4. Пропуск в необязательном языке — предупреждение (ADR-026).
5. Статус в файле не совпадает со статусом в `languages.json` — предупреждение
   (`LOC_STATUS_MISMATCH`); источник истины — `languages.json`.

## 7. Живое переключение

- Язык переключается в настройках без перезапуска (GDD §12.2).
- После смены: обновить все открытые экраны, tooltip, карточки, лог боя.
- Смена языка логируется (`Settings`, `oldLocale`, `newLocale`).
- Выбранный язык сохраняется в настройках и восстанавливается при запуске.
- Смена языка не меняет состояние партии и не влияет на RNG.
- В настройках показываются только языки со статусом `complete`
  и `visibleInSettings=true`; экспериментальные — только при явном включении
  режима показа экспериментальных языков.

## 8. Валидация и тесты

- `dotnet run --project src/Game.SimRunner -- validate` — полный валидатор контента,
  включая локализацию (exit 0 при успехе, 1 при ошибках).
- `tools/scripts/check-localization.ps1` — быстрая проверка структуры:
  паритет `ru`/`en`, отсутствие лишних ключей, соответствие `languages.json`
  набору файлов. Пропуски в необязательных языках — предупреждения.
- Тесты этапа 03 (`ContentValidatorTests`, `ContentPipelineTests`):
  паритет `ru`/`en`, отсутствие лишних ключей, статусы, фолбэк-цепочка,
  возврат ключа при полном промахе, наличие всех 26 языков.
- Тест подстановки плейсхолдеров — этап 06 (UI).
- Ручная проверка: переключение на всех основных экранах.

## 9. Шрифты и кодировка

- Шрифты — только с лицензией, допускающей использование и распространение
  (см. [docs/ASSET_LICENSES.md](ASSET_LICENSES.md)).
- Обязательна поддержка кириллицы и латиницы, включая `Ё/ё`.
- Для `la`, `cu`, `rue`, `szl`, `csb`, `hsb`, `dsb`, `cnr` требуется отдельная
  проверка шрифтового покрытия (диакритика, исторические знаки).
- Кодировка исходников — UTF-8; `.editorconfig` фиксирует charset.
- Godot-импорт шрифта настраивается в `game/assets/fonts`, не в коде.

## 10. Добавление языка

1. Новый ADR не требуется, если язык добавляется как данные.
2. Добавить запись в `languages.json` (код, `nameKey`, `script`, `status`,
   `visibleInSettings`, `fallback`, `requiresFontReview`).
3. Создать `<code>.json` с полным набором ключей `en` (для `complete`)
   или с допустимыми пропусками (для `draft`/`experimental`).
4. Добавить ключ `language.<code>.name` в `ru` и `en`.
5. Прогнать `validate` и `check-localization.ps1`.
6. Обновить этот документ и `docs/CHANGELOG.md`.
