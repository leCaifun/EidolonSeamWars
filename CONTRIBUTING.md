## 1. Порядок работы

1. Прочитать `AGENTS.md`, релевантные секции `docs/GDD.md`, `docs/DECISIONS.md` и
   последние записи `docs/WORKLOG.md`.
2. Сформулировать план из 3–7 пунктов.
3. Реализовать задачу полными файлами, без `TODO` в реализуемой части.
4. Выполнить `dotnet build`, `dotnet test` и `tools/scripts/validate`.
5. Обновить документы, `docs/WORKLOG.md` и `docs/CHANGELOG.md`.
6. Отчитаться: что сделано, как проверить, что не проверено, риски.

Задачи больше 7 файлов дробятся на подзадачи, кроме атомарных этапов из `prompts/`.

## 2. Архитектурные инварианты

Полный список — в `AGENTS.md` §2. Кратко:

- `src/Game.Core` не содержит `using Godot`.
- Весь игровой контент — JSON в `game/content/core`, стабильные ID, `schemaVersion`.
- Бой и экономика — целочисленная математика per-mille; float только в presentation.
- Случайность — только `Game.Core.Rng` (стримы `map` / `battle` / `loot` / `levelup`).
- Изменения состояния — команды, а не прямые мутации домена.
- Локализация — только ключи, `ru.json` + `en.json`.
- Никаких заимствованных имён, символов и ассетов (см. `docs/IP_SAFETY.md`).
- Никакого автобоя в игровых режимах; симуляция только в тестовом режиме/SimRunner.

## 3. Стиль кода

- Один публичный тип — один файл, имя файла совпадает с именем типа.
- Идентификаторы на английском, комментарии и документация на русском.
- Публичные методы домена имеют XML-комментарии на русском.
- Домен иммутабелен, где это возможно; мутации — только через команды.
- Никаких магических чисел: правила берутся из JSON или именованных констант.
- Ошибки валидируются на границах; исключения внутри домена содержат контекст.
- Новые NuGet-зависимости — только через `docs/DECISIONS.md`.

## 4. Тесты

- Фреймворк: xUnit, проект `tests/Game.Core.Tests`.
- На каждое правило — тест; на каждый баг — регрессионный тест.
- Тесты детерминированы: фиксированные сиды, без зависимости от времени и файловой системы.
- Запуск: `dotnet test EidolonSeamWars.sln -c Release`.
- Подробности: `docs/TESTING.md`.

## 5. Документация

Код без обновлённых документов не считается готовым. Матрица «изменил → обнови»
находится в `AGENTS.md` §4. Каждый документ имеет шапку (версия, статус, дата),
оглавление и ссылки на связанные документы.

## 6. Git и коммиты

Сейчас Git **не используется**: запрещены `git init/add/commit/push/tag/remote`,
GitVersion, hooks, `git describe`. История — в `docs/WORKLOG.md`.

Когда репозиторий будет загружен на GitHub:

- Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`, `balance:`).
- Одна задача — один логический коммит; сообщение указывается в записи WORKLOG.
- Ветки: `feat/<short-name>`, `fix/<short-name>`, `docs/<short-name>`.

## 7. Чек-лист перед сдачей

- [ ] `dotnet build` без ошибок.
- [ ] `dotnet test` зелёный.
- [ ] В `Game.Core` нет `using Godot`.
- [ ] Контент не захардкожен.
- [ ] Новые правила покрыты тестами.
- [ ] Логи добавлены в уязвимых местах.
- [ ] Документы обновлены, WORKLOG и CHANGELOG заполнены.
- [ ] Нет заимствованных имён/ассетов.
