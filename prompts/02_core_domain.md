## 1. Цель

Реализовать чистый домен `src/Game.Core` без Godot: базовые типы, армию, героя,
поселение, семь ресурсов, дневной тик и детерминированную математику. Геймплейный
UI и сцены не делать — это этапы 04–07.

## 3. Задачи

1. Добавить `IntegerMath` с `MulDiv` и округлением «половина от нуля» (ADR-022),
   с тестами на положительные, отрицательные и граничные значения.
2. Реализовать типы ресурсов: `ResourceKind` (7 значений), `ResourcePool`,
   операции дохода/траты с проверкой неотрицательности.
3. Реализовать `UnitDef` как контракт данных: стабильный строковый `Id`,
   `schemaVersion`, все поля GDD §8. Без хардкода конкретных юнитов.
4. Реализовать `Stack`: `UnitDefId`, `Count`, `VeterancyRank` (1–5), бонусы
   ветеранства по ADR-014, пороги 0/2/5/10/18.
5. Реализовать `Army`: 5 слотов, жёсткая проверка лидерства
   (`Σ leadershipCost × count ≤ capacity`), ёмкость героя = `hero.Leadership`,
   отряд без героя = 50 (ADR-006). Перегруз невозможен.
6. Реализовать `Hero` и `HeroStats`: уровень, опыт, soft cap 10, детерминированный
   `+1` к случайной weighted характеристике через `levelup`-стрим (ADR-011/017).
   Классы героев — данные, не код.
7. Реализовать `Settlement`: владелец, фракция, уровень 2/3/4 по фракции,
   гарнизон, слоты зданий, `Capture` с автоудалением зданий и сбросом уровня до 1
   (ADR-013).
8. Реализовать `DailyTick` в порядке ADR-004: доход → прирост (`stock`/`available`/
   `cap`) → регенерация жилищ → контракты найма → длительности → ход ИИ →
   автосохранение. ИИ на этом этапе — точка расширения, без реализации.
9. Реализовать формулы побега/выкупа/плена (ADR-012) как чистые функции с клампами.
10. Реализовать `EscapeResult`, `RansomQuote`, `CaptivityState` без UI.

Не реализовывать: карту, бой, сцены, JSON-загрузку, ИИ, сейвы в файлы.

## 4. Инварианты

- Только целочисленная математика; `float`/`double` в домене запрещены.
- Никаких `using Godot`.
- Никаких магических чисел: правила из JSON или именованные константы.
- Один публичный тип — один файл; имя файла = имя типа.
- Домен иммутабелен где возможно; мутации — через команды.
- Ошибки валидируются на границе и содержат контекст.
- Логирование — через `IGameLogger`, категории `Economy`, `Hero`, `Battle`.
- Конкретные юниты, фракции и здания в коде не упоминаются.

## 5. Тесты

Добавить в `tests/Game.Core.Tests`:

- `IntegerMathTests` — округление, переполнение, отрицательные значения.
- `ArmyLeadershipTests` — жёсткий лимит, отказ при превышении, отряд без героя.
- `VeterancyTests` — пороги 0/2/5/10/18 и бонусы рангов.
- `DailyTickTests` — порядок тика, прирост, cap, семь ресурсов.
- `SettlementCaptureTests` — автоудаление зданий, сброс уровня, смена шаблона.
- `EscapeRansomTests` — клампы 20…90, формула выкупа, запрет для защитника осады.
- `LevelUpTests` — детерминированность при одном сиде, soft cap 10.

## 7. Критерии приёмки

- `dotnet build EidolonSeamWars.sln -c Release` без ошибок.
- `dotnet test EidolonSeamWars.sln -c Release` зелёный.
- В `src/Game.Core` нет `using Godot` и нет `float`/`double`.
- Перегруз армии невозможен ни в одном тесте.
- Дневной тик детерминирован при одинаковом сиде.
- Захват поселения удаляет здания и сбрасывает уровень.
- Документы и WORKLOG обновлены.
