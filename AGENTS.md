# AGENTS.md — правила для AI-агентов проекта

Проект: «Эйдолон: Войны Шва».
Среда: OpenCode.
Git временно недоступен. Репозиторий будет загружен на GitHub позже.

## 0. Источник истины

При конфликте документов приоритет:
1. docs/GDD.md
2. docs/DECISIONS.md
3. docs/ARCHITECTURE.md
4. docs/ROADMAP.md
5. Остальные документы

Дизайн молча не менять. Если требуется изменение дизайна — сначала запись в docs/DECISIONS.md.

GDD большой: читать только релевантные секции, не обязательно целиком каждый раз.

## 1. Стек

- Godot 4.7.2 .NET
- C# / .NET 8
- xUnit
- JSON-контент
- Чистое ядро Game.Core без Godot-зависимостей

Использовать только документированный Godot 4.7.2 C# API.
Если не уверен в API — явно сказать, не выдумывать.
Новые NuGet-зависимости — только через docs/DECISIONS.md.

## 2. Инварианты

Нарушать запрещено:

1. src/Game.Core не содержит using Godot.
2. Весь контент — JSON + стабильные строковые ID + schemaVersion.
3. Никакого хардкода юнитов, фракций, зданий, заклинаний в коде.
4. Бой и экономика — целочисленная математика per-mille.
5. Float только в presentation-слое.
6. RNG только seeded-стримы: map / battle / loot / levelup.
7. Изменения состояния — команды: BattleCommand / MapCommand.
8. Сейвы: версия + миграции + безлимитные слоты.
9. Локализация: только ключи, ru.json + en.json.
10. Идентификаторы кода — EN, комментарии и документация — RU.
11. Логирование обязательно во всех уязвимых местах.
12. Никакого автобоя в игровых режимах.
13. Симуляция боя только в тестовом режиме / SimRunner.
14. Никаких охраняемых имён, символов, изображений, названий из чужих франшиз.

## 3. Рабочий цикл каждой задачи

1. Прочитай AGENTS.md.
2. Прочитай релевантные секции docs/GDD.md.
3. Прочитай docs/DECISIONS.md и последние записи docs/WORKLOG.md.
4. Выдай короткий план: 3–7 пунктов.
5. Реализуй полными файлами.
6. Запусти:
   - dotnet build
   - dotnet test
   - валидатор контента, если он уже есть
7. Обнови документацию.
8. Запиши задачу в docs/WORKLOG.md.
9. Обнови docs/CHANGELOG.md.
10. Дай отчёт:
   - что сделано
   - как проверить
   - что не проверено
   - риски

Если задача больше 7 файлов — дроби на подзадачи.

## Git и GitHub

Git доступен. Репозиторий публичный на GitHub.

Разрешено агенту:
- git add, git commit локально;
- conventional commits: feat/fix/chore/docs/test/refactor;
- создавать локальные ветки.

Запрещено агенту:
- git push, force-push, изменение remote;
- переписывание истории (rebase, reset --hard, amend опубликованного);
- коммитить секреты, токены, ключи;
- коммитить bin/, obj/, .godot/, logs/, saves/, builds/.

Push, слияние в main, теги и релизы выполняет пользователь.
Перед коммитом агент проверяет git status и .gitignore.

## Лицензирование

- Исходный код: лицензия в LICENSE.
- Контент и ассеты (game/content/, game/assets/): проприетарные, LICENSE-CONTENT.md.
- Название и логотип: TRADEMARK.md.
- Моды и примеры: отдельная разрешительная лицензия.
- Не добавлять ассеты с неясной лицензией. Каждый ассет — в ASSET_LICENSES.md.

## 6. Стиль кода

- Один публичный тип = один файл.
- Имя файла = имя типа.
- Домен иммутабельный где возможно.
- Мутации только через команды.
- Никаких магических чисел: правила из JSON или именованные константы.
- Публичные методы домена dokumentировать XML-комментариями на русском.
- Ошибки валидировать на границах системы.
- Внутри домена исключения должны содержать контекст.

## 7. Запреты

- Не менять инварианты ради «так проще».
- Не добавлять фичи вне текущего этапа ROADMAP.
- Не хардкодить контент.
- Не оставлять TODO в реализуемой части.
- Не делать фальшивые заглушки.
- Заглушки допустимы только для нереализованных режимов UI и должны быть честными: disabled + «В разработке».

## 8. Definition of Done

Задача готова только если:

- компилируется;
- тесты зелёные;
- валидатор контента прошёл, если применимо;
- документы обновлены;
- WORKLOG записан;
- CHANGELOG обновлён;
- логи добавлены;
- выдан отчёт о проверке.

## 9. Контент
- Схемы, DTO, загрузчик, merge и валидатор — в src/Game.Core/Content.
- CLI validate — в Game.SimRunner, скрипты вызывает его.
- Прямой файловый IO в Core запрещён, только через абстракцию.
- Все отображаемые строки — ключи локализации.
- Дробные числа в JSON запрещены, только целые.
- Неизвестные поля в JSON — ошибка, не предупреждение.

## 10. Локализация

- Список языков живёт в `game/content/core/localization/languages.json`.
- Обязательные языки для полной валидации: `ru`, `en`.
- Остальные языки могут быть `draft` или `experimental`.
- Пропущенные ключи в необязательных языках — предупреждение, не ошибка.
- В настройках показывать только языки со статусом `complete` и `visibleInSettings=true`.
- Фолбэк: выбранный язык → `fallback` → глобальный `fallbackLanguage` → ключ как строка.
- Для церковнославянского, русинского, силезского, кашубского и лужицких языков требуется проверка шрифтов.
